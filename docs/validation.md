# 公式値との照合

このパッケージは「気象庁が公表している値を可能な限り再現できる」ことを目指しています。

気象庁は長周期地震動の観測結果ページで、観測点ごとに**波形そのもの**と**波形から気象庁が導いた値**の両方を公開しています。

## 検証の2つの層

このページで扱う検証には性質の異なる2つの層があります。

**アルゴリズムそのものの検証**は、気象庁が計算過程の中間値まで明示している記録に対して行うのが最も直接的です。2000年鳥取県西部地震(米子)の記録がこれに当たり、公表された計測震度5.1(丸め後の表示値)は一致し、公表されている閾値加速度127.85 galとも約0.05%の相対差で近い値が得られます。この0.05%は波形の丸めでは説明できない差で、この記録が公式フォーマット仕様の対象外にある古い形式のアーカイブファイルであることに関係すると考えられますが、原因は特定できていません(下記「単一記録によるアルゴリズム検証」)。長周期地震動観測結果ページの`velsp.csv`(絶対速度応答スペクトル)も、同ページの見方に「絶対速度応答スペクトルグラフの作成に用いたデータのcsvファイル」と明記されており、同じ加速度波形から気象庁自身が計算した値であることが確認できるため、268観測点規模でのアルゴリズム検証として扱えます。

**運用データ製品間の整合性チェック**は、それに対してもう一段弱い検証です。`max.csv`の震度列は、気象庁の資料で「震度情報で発表した震度」と定義されており、加速度・速度・変位の列(「観測期間における...の最大値」)とは異なる書き方をされています。つまりこの震度は、同じページで公開されている加速度波形から改めて計算した値であるとは限らず、気象庁内の別のシステム(震度情報)から転記された値です。したがって、これと本パッケージの再計算値を突き合わせる作業は、pyshindoのアルゴリズムそのものの検証というより、「気象庁の2つのデータ製品が同じ地震について整合しているか」の確認に近いものです。以下の「震度階級」の節はこの前提で読んでください。

## 照合するもの

| 公表ファイル | 公表されている量 | 対応する計算 |
| --- | --- | --- |
| `data/max.csv` | 震度、最大加速度(3成分と3成分合成)、最大速度(3成分と3成分合成) | `calculate_measured_intensity`、`apply_ground_motion_high_pass` + `component_peak_velocity`/`peak_ground_velocity` |
| `data/level.csv` | 長周期地震動階級(全体)、周期帯別階級(1秒台〜7秒台) | `calculate_long_period_class` |
| `station/data/velsp/*_velsp.csv` | 絶対速度応答スペクトル(減衰5%、水平合成) | `LongPeriodResult.sva_cm_s` |

## 解釈

### 長周期地震動階級: 完全一致

268観測点すべてで、全体の階級と7つの周期帯別階級が公表値と一致しました。応答スペクトルそのものも、記録の最大値では 1e-05 の水準で一致します。周期ごとに見ると最悪 1e-03 まで開きますが、これは応答が小さい周期での相対誤差で、階級判定には影響しません。

### 震度階級: 268点中1点だけ不一致(運用データ製品間の整合性チェック)

`47256 那須塩原市蟇沼` で、公開加速度CSVから再計算した計測震度は2.4(震度2)、`max.csv`に記載された震度情報の発表値は震度3でした。公開波形から得た0.3秒閾値は5.926 gal、未丸め計測震度は約2.486です。気象庁の二段階丸めを踏まえると、表示震度が2.5になる境界は未丸め値で約2.495・閾値加速度で約5.991 galで、差は未丸め震度にして約0.0095、加速度にして約1.1%です。

前節のとおり、`max.csv`の震度は「震度情報で発表した震度」であり、同ページの公開加速度CSVから改めて計算した値だとは定義されていません。震度情報自体は気象庁方式の計測震度アルゴリズムで算出されているはずなので、アルゴリズムの種類が違うことが原因とは考えにくいですが、運用時の計算に使われた記録区間・元波形の精度・公開CSVへの変換処理を気象庁の公開資料から特定することはできません。したがって、この不一致の原因は現時点では特定できないというのが正確なところです。境界にごく近い値なので小さな差で階級が変わりやすいことは確かですが、これを計測震度アルゴリズム自体の許容誤差とみなすべきではありません。

### 最大加速度: 誤差の水準は波形の丸めと整合する

相対誤差の中央値は5e-05で、これは公開波形が小数3桁に丸められていることの影響とほぼ同じ大きさです。公開波形の数値化精度が気象庁の運用時の元データと異なる場合、完全一致は保証されません。ただし、気象庁内部でのデータの精度や丸め規則そのものは公開資料からは確認できないため、誤差の原因を波形の丸めだけに断定することはできません。いずれにしても、この誤差の水準は「波形の解釈が正しい」ことの確認としては十分です。

### 最大速度: 20秒ハイパスを先に適用すると再現できる

生の加速度をそのまま累積台形積分すると、最大速度は2〜3%ずれます(ずれの向きは観測点ごとに一定でないため、単純な倍率の違いではありません)。台形積分以外の規約(`remove_offset`、`detrend_acceleration`、速度への零位相ハイパス0.05〜0.2 Hzなど)を色々試しても最良で1.95%程度にしかならず、最大加速度で達成した1e-05の水準には遠く及びませんでした。

しかしこのデータは「長周期地震動の観測結果」ページの一部であり、同じページの`level.csv`・`velsp.csv`は長周期地震動階級の計算(20秒の2次ハイパス→積分→階級判定)と地続きです。そこで、**最大速度を求める前に、長周期地震動階級の計算で使っているのと同じ20秒ハイパスを3成分の加速度に適用してから積分する**と試したところ、相対誤差が劇的に改善しました:

| 前処理                                    | 相対誤差の中央値 |
| ------------------------------------------ | ---------------- |
| なし(生の加速度を台形積分)                 | 2.1〜2.5%         |
| 速度に零位相2次ハイパス(最良ケース)        | 1.95%             |
| **20秒ハイパスを加速度に適用してから積分** | **0.009〜0.011%** |

これは最大加速度(5e-05)と同じ「波形の丸めが下限」の水準まで一致しており、179点中178点・89点中89点が相対誤差1%以内に収まります(`--spectra`を使わない全観測点での結果)。`pyshindo.long_period.apply_ground_motion_high_pass`として公開しており、使い方は次のとおりです:

```python
from pyshindo.long_period import apply_ground_motion_high_pass
from pyshindo.velocity import peak_ground_velocity

filtered = apply_ground_motion_high_pass(acceleration, sampling_rate_hz, unit="gal")
pgv = peak_ground_velocity(filtered, sampling_rate_hz, unit="gal")
```

ただし [観測結果ページの見方](https://www.data.jma.go.jp/eew/data/ltpgm_explain/about_contents.pdf) はこの手順を明記しておらず、「これらの地動最大値の値については、気象庁が発行している強震観測報告に掲載している値とは異なる場合があります」という注記があるのみです。この一致は268観測点にわたる実証的な発見であり、一次資料に明記された手順の再現ではないことに注意してください。この特定のデータ製品(長周期地震動観測結果ページ)以外の文脈(K-NET/KiK-net等の一般的な強震記録)でも同じ関係が成り立つかは確認していません。`apply_ground_motion_high_pass`を使わない生の`peak_ground_velocity`/`component_peak_velocity`の既定動作(ベースライン処理なしの台形積分)は変更していません。

## 単一記録によるアルゴリズム検証: 2000年鳥取県西部地震(米子)

気象庁の計測震度の計算解説ページはこの記録を計算例として使っており、計測震度5.1に加えて閾値加速度127.85 galという中間値まで明示しています。この記録を実際にダウンロードして`calculate_measured_intensity`にかけると、丸め後の表示震度は5.1で一致しますが、丸め前の閾値加速度は127.916 galで、公表値127.85 galとの相対差は約0.05%(絶対差0.066 gal)あります。

この差は波形の丸めでは説明できません。公開波形は小数3桁(0.001 gal刻み)で、丸め幅の範囲内で元波形を200通りランダムに揺らして計算し直しても、閾値の標準偏差は0.0001 gal程度にしかならず、必要な0.066 galという差の600倍以上小さいことを確認しています。閾値を与えているサンプルは記録開始19.44秒後、300秒の記録のちょうど本震の最中にあり、FFTの端効果でもありません。

原因として有力なのは、この記録のファイル自体の性質です。ヘッダを正しい文字コード(cp932)で読むと、観測点名が`米子市博労町（旧）`となっており、「(旧)」、すなわち廃止済み観測点の記録であることが明記されています。さらに1行目には、気象庁の公式フォーマット仕様([加速度データのフォーマット](https://ds.data.jma.go.jp/eqev/data/kyoshin/jishin/format.html)、観測点コード・緯度・経度・サンプリング周波数・単位・開始時刻・成分名の7行構成)には存在しない数値(`7.3`はこの地震のマグニチュード、`36805.5627072`は1900年起点のシリアル日付とみられる値など)が詰め込まれています。つまりこれは公式フォーマット仕様の対象外にある、古い形式のアーカイブファイルです。この事実から、公開されている本ファイルと気象庁の計算解説ページが参照した元データとの間で、何らかの再処理や書式変換を経ている可能性が考えられますが、その具体的な内容は公開資料からは特定できていません。

長周期地震動観測結果ページの268観測点よりサンプル数は少なく(1件)、閾値加速度は上記のとおり厳密には一致しないものの、気象庁自身が算出過程の中間値まで明示した記録に対する検証という点で、震度アルゴリズムの正しさを示す根拠としては依然として価値があります。震度5.1という最終的な表示値の一致は、丸めのマージンを考慮しても閾値0.05%のずれでは動きません。

この記録はリポジトリに同梱しておらず、ダウンロードを伴うため自動テストには含めていません。詳細は[`docs/data.md`](data.md)を参照してください。

## 再現方法

```bash
python scripts/validate_official.py --event 20260823020050
```

初回はおよそ20 MBをダウンロードして `.cache/pyshindo/validation/` に保存し、以降は再利用します。`--spectra N` で応答スペクトルを照合する観測点数(震度の大きい順)を指定できます。

このスクリプトはテストスイートには含めていません。ネットワークが必要であることに加えて、配信元が保持しているのは直近数週間のイベントだけで、上の地震IDもいずれ解決しなくなるためです。現在有効なイベントIDは[長周期地震動の観測結果](https://www.data.jma.go.jp/eew/data/ltpgm/eq_list.php)で確認できます。上の結果表は、その時点の実行結果の記録という位置付けです。
