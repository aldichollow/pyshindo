# アルゴリズム解説

`pyshindo` は「記録全体を用いるFFT計算(計測震度)」と「逐次入力に対するリアルタイム近似」を明確に分離しています。両者は同じ値を目標にしますが、同一の演算ではありません。

## 1. 入力の前提

標準的な入力は、水平2成分と上下1成分からなる直交3成分の加速度です。配列形状は `(サンプル数, 3)`、単位は `gal`、`m/s^2`、`g` のいずれかを指定します。内部では倍精度浮動小数点とgalへ変換して処理します。

100 Hzを基準とし、それ以外のサンプリング周波数も受け付けますが警告を出します(0.3秒が整数サンプルにならない、フィルタの安定性・近似誤差が変わる、公開資料の検証条件が100 Hzである、など)。非整数となる継続時間は、既定では必要時間を下回らない `ceil` でサンプル数に変換します。

## 2. 計測震度のFFT参照計算

各軸をフーリエ変換し、周波数 `f [Hz]` に対して次の振幅応答を掛けてから逆変換します。

```
F(f) = F_P(f) * F_H(f) * F_L(f)

F_P(f) = sqrt(1/f)                                          周期効果
F_H(f) = (1 + 0.694y^2 + 0.241y^4 + 0.0557y^6
          + 0.009664y^8 + 0.00134y^10 + 0.000155y^12)^-1/2   ハイカット (y = f/10)
F_L(f) = sqrt(1 - exp(-(f/0.5)^3))                            ローカット
```

`f=0` では周期効果単体は発散しますが、ローカットとの積の極限は0になるため、総合応答は0とします。FFT長は記録長と同じで、ゼロパディング・窓関数・平均除去・トレンド除去は暗黙には行いません(勝手に追加すると別の演算になるため)。

逆変換後の3軸 `a_x(t), a_y(t), a_z(t)` から `a(t) = sqrt(a_x^2 + a_y^2 + a_z^2)` を計算し、大きい順に並べたときの30番目(100 Hzで0.3秒相当)の値を閾値 `a_0` とします。全要素をソートせず `numpy.partition` の順序統計量を使います。同値が複数ある場合、`a(t) >= a_0` となる数が30を超えることがありますが、離散データの自然な帰結として閾値は動かしません。

震度は `I = 2*log10(a_0) + 0.94` で連続値 (`intensity_raw`) を得ます。表示値(`intensity`)は気象庁の説明どおり「小数第3位を四捨五入し、その後小数第2位を切り捨て」ます。境界で二進浮動小数点の丸め誤差に依存しないよう、`report_intensity()` は十進演算を使います。

`calculate_measured_intensity()` は連続値・表示値・震度階級・閾値・フィルタ後波形・PGA・`timing`(各段階の実測時間)などをまとめて返します。

## 3. リアルタイム震度

周波数領域フィルタを因果的な時間領域IIRフィルタで近似します。3つの設計があります。

- `kunugi2008`: 最初の近似フィルタ
- `kunugi2012`: 近似誤差を改善した6段の2次フィルタ(100 Hzの既定)
- `jp7681907_lowrate`: 低いサンプリング周波数でも安定性を確保する一般化係数

`RealtimeFilter.AUTO` は80 Hz未満で低レート設計へ切り替えます。実際に使われた設計名は結果に残ります。

`kunugi2012`/`jp7681907_lowrate`は、周期効果(A1)・7 Hz付近の3因子(A2-A4)・補正(A5)・12/20/30 Hzの3段ローパス(A6-A8)という、8つの解析的因子(A1-A8はKunugi et al. (2013)の二次資料でよく使われる表記で、一次論文と直接照合したものではない)+ゲインの積で近似されており(`kunugi2008`は5因子+ゲイン)、実際にフィルタリングする際は隣接する因子を2次セクションに融合して6段(kunugi2008は3段)のSOSにしています。`design_realtime_filter()`が返す`RecursiveFilterDesign.stages`には、融合前の各因子が名前・特性周波数つきで個別に入っており、`filter_stage_response()`で1因子ずつ、または`pyshindo.plotting.filter_stages_figure()`でまとめて特性を確認できます。各因子を独立にカスケードした結果は、結合済みの`.sos`と一致します(浮動小数点誤差の範囲内)。

各サンプルについて、IIRフィルタ通過 → 3成分合成 → 直近60秒中の0.3秒相当の順序統計量を更新 → `I_r(t) = 2*log10(a_0(t)) + 0.94` を計算、という流れです。最初の0.3秒分が揃うまでは `NaN`。ゼロ入力が続くと閾値は0になり `-inf` になります(対数式の自然な結果)。

60秒窓(100 Hzで最大6000点)の30番目の値は、毎回全点をソートする代わりに2ヒープ(上位30点の最小ヒープ+残りの最大ヒープ、遅延削除つき)で償却 `O(log W)` で更新します。特許例にある震度0.01刻みのヒストグラム離散化は使わず、合成加速度そのものへの厳密な順序統計量を保持します。

`RealtimeIntensityEstimator` はIIR状態・60秒窓・累積最大値を保持し、チャンク境界に依存しない結果を返します。`process()`(チャンク一括、SciPyの`sosfilt`)と`process_sample()`(1サンプルずつ、Pythonのfloat演算)は同一インスタンス上で自由に混在できます。ただし両者は同じ漸化式を異なる経路で計算するため、浮動小数点の非結合性により長いストリームでは数ULP相当の差が蓄積し得ます(混在自体による誤差ではなく、`process_sample()`単体でも生じる性質です)。各呼び出しの所要時間は`RealtimeChunk.timing` / `RealtimeSample.elapsed_s`として結果に含まれます。

入力の成分数は最初のチャンクで固定されます。`reset()` で全状態を初期化できます。

## 4. 前処理

`remove_offset()` / `detrend_acceleration()` / `cosine_taper()` / `resample_acceleration()` は実務上便利ですが、計測震度の定義に暗黙に含まれるものではなく、明示的に呼ぶ必要があります。生のMEMS加速度には重力とオフセットが含まれ得るため、大きなDC成分をゼロ状態IIRへ突然入力すると初期過渡応答が生じます。必要な基線処理はリアルタイム処理の上流で行ってください。

## 5. 短いレコード・欠損への注意

`calculate_measured_intensity` は、0.3秒条件に必要なサンプル数を下回る場合のみ `InsufficientDataError` を送出します。1サンプルやゼロ入力のような「短すぎる」レコードでもエラーにはならず、DCで0になるフィルタの定義どおり `-inf` / 震度階級`0`を返します。定義上正しい挙動ですが、意図的な結果であることに注意してください。`NaN`・無限大の入力は受け付けません。

## 6. 用語の区別

- `intensity_raw`: 数式から得た連続値
- `intensity`: 気象庁の十進処理を適用した1桁表示値
- `scale`: 震度0〜7の階級
- `approximate_intensity_raw`: リアルタイム計算で得た記録内の最大値

内部計算・比較・誤差評価には丸め前の値を使い、表示・階級化の段階でのみ丸めます。

## 7. 可視化(`pyshindo.plotting`、`pip install pyshindo[plot]`)

Plotlyを使った補助的な可視化レイヤーで、数値結果には関与しません。震度1〜7の配色はJMA Webカラーガイド(表2-2)に準拠し、ガイドに定義のない震度0は `#F7F8FA` を独自に採用しています。
